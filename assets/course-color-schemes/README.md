# 课程配色方案

每个 `.json` 文件定义一套普通课程配色。应用通过 Metro 的 `require.context` 自动发现本目录第一层的 JSON，不需要维护手写的导入列表或方案枚举。经典配色 `old` 是默认方案，应保留其文件和 ID。

新增方案时，在这里添加一个 JSON 文件，重新构建应用即可包含它。开发期间由 Metro 监听目录变化；如果新文件尚未出现在列表中，重新加载应用。已安装的应用不会直接扫描电脑上的源码目录。

```json
{
  "id": "ocean-breeze",
  "name": "海风",
  "colors": [
    "#307D81",
    "#38848D",
    "#4E7790",
    "#41888C",
    "#3E8D9B",
    "#5689A5",
    "#519196",
    "#4A96AD",
    "#5A9DBD",
    "#619AA0",
    "#5CA5B3",
    "#5CA8CD",
    "#66A08F",
    "#75AAB1",
    "#5BB3DD",
    "#7CAF94",
    "#87B9C1",
    "#79BDDE",
    "#8CB7A5",
    "#92BAC5",
    "#9AC3D7",
    "#91C5C6",
    "#9AD1CD",
    "#A2CAE7",
    "#A1C7A1"
  ]
}
```

内置 JSON 文件字段规则：

- `id`：每套方案的 ID 必须唯一。兼容原有以小写字母开头、包含小写字母/数字/短横线的 1–64 位 ID，也支持本机生成的 6 位小写十六进制 ID。
- `name`：内置文件及旧存储继续兼容去除首尾空白后 1–40 个字符的名称，不会因编辑页的新名称限制而丢失旧方案。
- `colors`：必须恰好包含 25 个不重复的 `#RRGGBB` 颜色，大小写均可，导入时统一为大写。颜色顺序用于切换方案时映射原有课程色号。

应用中的入口是「课程表设置 → 课程配色」，点击带加号的新增配色卡进入「编辑配色」页。名称在独立输入框填写，去除首尾空白后不得为空，最多 16 个长度单位：ASCII 字符算 1，其他 Unicode 字符算 2，因此最多为 8 个汉字或 16 个 ASCII 字符。修改旧方案时也按此规则验证新名称；只读取旧数据时不会截断或改名。

颜色输入框支持直接粘贴 25 色数组、包含 `colors` 数组的 JSON 对象，或单独的 `"colors": [...]` 字段片段。完整内置 JSON 也可以粘贴，编辑器仅提取其中的 `colors`；名称仍使用独立输入框的内容。颜色必须恰好 25 个，均为不重复的 `#RRGGBB`，保存时统一为大写。无需手动填写 ID：新建时在本机生成 6 位小写十六进制短哈希，与已有 ID 冲突时重新生成；编辑保留原 ID 及列表顺序。不读取文件或自动读取剪贴板，不需要新增原生依赖。

自定义方案保存在本机 AsyncStorage 的 `custom_course_color_schemes_v1` 中，重启后会先恢复这些方案，再读取所选配色和课表缓存。它们不会写入打包后的 `assets`，也不会上传到云端。颜色文本最多接受 32768 个字符，本机最多保存 5 套自定义方案，内置方案不占用这 5 个名额。保存满 5 套时隐藏加号新增卡，仍可以编辑已有方案；删除成功腾出名额后重新显示加号。

在列表中选择自定义配色后，再次点击已选中的卡片即可打开编辑弹窗；左上角提供删除操作，右上角用于保存。内置配色不能编辑或删除。删除当前使用的方案前会先切回经典配色；若删除保存失败，方案仍保留在列表中。新建、编辑和删除共用串行写入队列，持久化成功后才更新列表；编辑保存失败时保留原名称和颜色。

若已保存的配色记录损坏、颜色数量不是 25，或与更新后的内置 ID 冲突，加载时会跳过无效记录并提示，保留其原始存储，课表仍可使用其余方案。已有数据超过 5 套时，按原顺序加载前 5 套有效方案，多余记录仍保留在原始存储中。无效记录不占用名额。之后新建、编辑或删除方案时，会先将原始文本保存到 `custom_course_color_schemes_recovery_v1`，再更新方案列表；备份失败则不会覆盖原数据。

切换配色只影响普通课程及好友课表。考试、自定义课程的指定颜色保持原样；桌面小组件随课表缓存更新。切换时沿用原有课程的色号位置；恢复旧版课表缓存时，超出新色表范围的色号按 25 色循环映射。为新课程分配颜色时，一轮 25 种颜色用完后循环复用，不再退回黑色。

课表的显示补偿与上述原色、存储和缓存更新相互独立。六位 HEX 颜色在深浅模式下都以 `rgba(..., 0.75)` 绘制背景；透明度不会施加到文字或整个卡片。配色列表和编辑页的预览继续显示 JSON 原色，作为方案本身的参考。

`utils/course-color-display.ts` 在 OKLCH 中固定原色的色相，适度调整明度和彩度。默认主题以浅色 `#F7F7F7`、深色 `#121212` 为背景参考，比较每个候选经过 75% 不透明度混合后的 OKLab 色差；原色也参与比较，避免补偿反而增加参考背景上的误差。候选超出 sRGB 色域时压缩彩度，避免直接截断 RGB 导致偏色。显示结果按原色和背景配置缓存在有容量上限的内存映射中，不写回课程或配色存储。

壁纸的实际像素并不固定，因此使用独立的中性灰参考，按「壁纸压暗」选项计算黑色遮罩，并减弱补偿幅度；这只能改善整体观感，不能抵消图片每个位置的颜色。普通课程、考试和自定义单课共用显示补偿，基础颜色仍各自保留；非本周课程的灰色仅使用统一透明度，不增强颜色。已有非六位 HEX 值继续原样显示。固定透明度下有些原色无法完整还原，最终仍需结合设备上的背景和文字可读性检查。
